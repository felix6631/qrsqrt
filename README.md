# rsqrt 벤치마크: Quake 트릭 vs 하드웨어 근사 (Apple M4)

`1/sqrt(x)`를 계산하는 여러 방법의 **속도와 정확도**를 함수 포인터 기반으로 비교하는 작은 벤치마크입니다.
1999년의 Fast Inverse Square Root(Quake III) 트릭이 현대 CPU(ARM64, Apple M4)에서도 의미가 있는지 확인하는 것이 목적입니다.

## 파일 구성

| 파일 | 설명 |
|---|---|
| `qrsqrt.c` | `double q_rsqrt(double)` 구현 (매직 넘버 + 뉴턴 1회) |
| `main.c` | 벤치마크 본체. `TABLE[]`에 함수 포인터를 등록해 측정 |

## 빌드 및 실행

```sh
clang -O2 main.c -o bench -lm
./bench
```

- ARM64(`__aarch64__`)에서는 `frsqrte` 기반 구현이 자동으로 포함됩니다.
- 측정할 함수를 추가하려면 `main.c`의 `TABLE[]`에 `{ "이름", 함수포인터 }`를 한 줄 넣으면 됩니다. **첫 항목이 기준**(속도 배율과 오차 계산의 기준)입니다.

## 측정 조건

- 환경: Apple M4, `-O2`
- 입력 범위: `[1.0, 10.0]`, 균등 간격 20,000,000개
- 시간: 7회 반복 중 **최솟값** (워밍업 1회 포함)
- 오차: 기준 `1.0 / sqrt(x)` 대비 **상대 오차** `|f(x) - ref| / ref`
- 누산기 4개로 덧셈 의존성 체인을 끊어 throughput 위주로 측정, `noinline`으로 특정 함수만 인라인되는 불공정 방지

## 결과

| 함수 | 시간(s) | 배속 | 최대 상대오차 | 평균 상대오차 |
|---|---:|---:|---:|---:|
| `1/sqrt(x)` (기준) | 0.0142 | 1.00x | 0 | 0 |
| `q_rsqrt` | 0.0117 | 1.21x | 1.751e-03 | 9.593e-04 |
| `frsqrte` only | 0.0102 | 1.39x | 3.277e-03 | 9.596e-04 |
| `frsqrte` + 뉴턴 1회 | 0.0101 | **1.40x** | 1.612e-05 | 2.074e-06 |
| `frsqrte` + 뉴턴 2회 | 0.0170 | 0.83x | 3.900e-10 | 1.600e-11 |
| `frsqrte` + 뉴턴 3회 | 0.0174 | 0.81x | 3.835e-16 | 6.795e-17 |

(checksum은 기준, 뉴턴 2회, 3회가 소수점 셋째 자리까지 일치해 구현이 올바름을 확인했습니다.)

## 해석

1. **정확도 1e-3 수준에서는 `q_rsqrt`보다 `frsqrte`가 빠릅니다.**
   `frsqrte` 단독은 `q_rsqrt`와 비슷한 정확도(최대 오차 3.3e-3 vs 1.75e-3)에서 1.39x로, `q_rsqrt`의 1.21x보다 빠릅니다.
   Quake 트릭은 부동소수점 ↔ 정수 레지스터 이동(`fmov`)이 필요하지만, `frsqrte`는 부동소수점 레지스터 안에서 끝나기 때문으로 보입니다(가설).

2. **`frsqrte` + 뉴턴 1회가 가장 가성비가 좋습니다.**
   `frsqrte` 단독과 거의 같은 시간에 오차가 약 200배 줄어듭니다(3.3e-3 → 1.6e-5). 이 측정에서는 뉴턴 1회가 사실상 공짜입니다.

3. **정밀도를 더 올리면 오히려 기준(`1/sqrt`)보다 느려집니다.**
   뉴턴 2회(오차 ~4e-10)부터 기준보다 느려집니다(0.83x). Apple 코어의 `fsqrt`/`fdiv`가 충분히 빨라서, 거의 double 정밀도가 필요하면 그냥 `1/sqrt(x)`를 쓰는 편이 낫습니다.
   뉴턴 1회 → 2회에서 시간이 크게 뛰는(0.0101 → 0.0170) 정확한 이유는 확인하지 않았습니다. 의존성 체인 길이와 파이프라인 폭의 관계일 가능성이 있어, `-S`로 어셈블리를 보거나 별도 실험이 필요합니다.

4. **Quake 트릭의 이점은 M4에서 작습니다.**
   x86 시절에는 수 배 차이가 났지만, 여기서는 1.2배 수준입니다. 대신 정확도(~9비트)를 내줘야 하므로 현대 ARM64에서는 `frsqrte` 계열이 더 합리적인 선택입니다.

## 한계

- **함수 포인터(간접 호출) 오버헤드**가 모든 항목에 동일하게 더해져, 인라인된 실제 사용 환경에서의 차이는 더 크거나 다를 수 있습니다.
- **스칼라 비교**입니다. `1/sqrt(x)`는 배열 단위로 처리하면 NEON(2 lanes)으로 벡터화될 수 있고, `vrsqrteq_f64` 기반 구현과의 비교는 이 벤치에 포함되어 있지 않습니다.
- 입력 범위가 `[1, 10]`로 좁습니다. 매우 작거나 큰 값, 0, 음수, subnormal에서의 동작은 측정하지 않았습니다.
- 측정은 한 대의 머신(M4)에서 한 번 수행한 결과입니다. 전력 상태, 성능/효율 코어 배치에 따라 편차가 있을 수 있습니다.

## 참고

- `frsqrte`: ARM64의 역제곱근 추정 명령어 (약 8비트 정확도), `frsqrts`: 뉴턴 스텝 보조 명령어 `(3 - a*b) / 2`
- double용 매직 넘버: `0x5fe6eb50c7b537a9`
